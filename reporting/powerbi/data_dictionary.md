# Power BI Data Dictionary

These tables are generated by `python -m reporting.export_powerbi_csvs` under `outputs/powerbi/`.

## advisor_kpis.csv

Grain: one row per advisor, branch, firm, and month.

Primary / natural keys:

- `month_end_date`
- `firm_crd_number`
- `branch_id`
- `advisor_id`

Key fields:

- `advisor_name`: synthetic advisor display name.
- `branch_name`: synthetic branch display name.
- `account_count`: distinct accounts assigned to the advisor for the month.
- `beginning_aum`: beginning assets under management.
- `ending_aum`: ending assets under management.
- `net_new_assets`: monthly net new assets.
- `revenue`: monthly advisory revenue.
- `avg_fee_rate`: average fee rate across advisor account-month rows.
- `aum_growth_rate`: `(ending_aum - beginning_aum) / beginning_aum`.
- `revenue_per_account`: `revenue / account_count`.

Metric definitions:

- Total AUM should generally use `ending_aum`.
- Revenue measures should sum `revenue`.
- AUM growth is a monthly aggregate growth rate at this grain.

Notes:

- Advisor, account, and performance records are synthetic private-style data.
- Firm CRD values may be seeded from real/public SEC ADV firm context when available, but advisor-level rows are synthetic.

## branch_kpis.csv

Grain: one row per branch, firm, and month.

Primary / natural keys:

- `month_end_date`
- `firm_crd_number`
- `branch_id`

Key fields:

- `branch_name`: synthetic branch display name.
- `branch_region`: generated region label.
- `account_count`: distinct accounts in the branch for the month.
- `advisor_count`: distinct advisors in the branch for the month.
- `beginning_aum`, `ending_aum`, `net_new_assets`, `revenue`: monthly financial KPIs.
- `avg_fee_rate`: average fee rate across branch account-month rows.
- `aum_growth_rate`: monthly branch AUM growth rate.
- `revenue_per_account`: branch revenue divided by account count.

Metric definitions:

- Branch rankings can use `ending_aum`, `revenue`, or `net_new_assets`.
- Revenue per advisor can be calculated as `revenue / advisor_count`.

Notes:

- Branch records are synthetic and should not be presented as real office performance.

## firm_kpis.csv

Grain: one row per firm and month.

Primary / natural keys:

- `month_end_date`
- `firm_crd_number`

Key fields:

- `account_count`: distinct accounts at the firm for the month.
- `advisor_count`: distinct advisors at the firm for the month.
- `beginning_aum`, `ending_aum`, `net_new_assets`, `revenue`: monthly firm KPIs.
- `avg_fee_rate`: average firm fee rate.
- `aum_growth_rate`: monthly firm AUM growth rate.
- `revenue_per_account`: firm revenue divided by account count.

Metric definitions:

- Executive finance cards can use this table to avoid double counting advisor or branch rows.
- Use `ending_aum` for current AUM and `revenue` for monthly revenue.

Notes:

- Firm identifiers may reflect real/public SEC ADV-style seed data. Monthly operating metrics are synthetic.

## qa_metrics.csv

Grain: one row per evaluation scope, detection family, rule name, and selected threshold.

Primary / natural keys:

- `evaluation_scope`
- `detection_family`
- `rule_name`
- `threshold_label`

Key fields:

- `true_positives`: detections matched to seeded ground truth.
- `false_positives`: detections without a matching seeded issue.
- `false_negatives`: seeded issues not detected.
- `ground_truth_count`: seeded issue count in scope.
- `detection_count`: detection count in scope.
- `precision`: `true_positives / (true_positives + false_positives)`.
- `recall`: `true_positives / (true_positives + false_negatives)`.
- `false_positive_rate`: `false_positives / detection_count`.
- `f1_score`: harmonic mean of precision and recall.

Metric definitions:

- Use the `overall` row for executive QA cards.
- Use detection-family rows for hard-rule versus statistical-rule summaries.

Notes:

- QA metrics are calculated against intentionally seeded errors in synthetic data.
- These metrics are useful for reviewer tradeoff analysis, not regulatory claims.

## qa_threshold_comparison.csv

Grain: one row per evaluation scope, detection family, rule name, and tested threshold label.

Primary / natural keys:

- `threshold_label`
- `evaluation_scope`
- `detection_family`
- `rule_name`

Key fields:

- Same metric fields as `qa_metrics.csv`.
- `threshold_label`: tested z-score and IQR threshold combination, such as `z=2.5_iqr=2.0`.

Metric definitions:

- Compare precision, recall, false-positive rate, and F1 score by threshold.
- Use overall rows for threshold selection visuals.

Notes:

- Threshold comparison supports the QA operating-point story: catching more bad finance data versus controlling reviewer workload.
